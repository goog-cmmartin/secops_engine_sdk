# SIEM Tuning & Filtering Guide (Google SecOps GoogleSQL)

This guide provides a structured methodology and operational queries for reducing log volume, eliminating redundant telemetry, micro-filtering benign noise at the collection layer, and tuning detection rules.

All queries are refactored for **native Google SecOps GoogleSQL** (`execute_dashboard_query` with `dialect="SQL"`), querying the native `events` table directly without BigQuery linked export prefixes (`udm.`).

---

## 0. Key Refactoring Rules: BigQuery SQL vs. SecOps GoogleSQL

| BigQuery Linked Export (`secops_linked_data`) | Google SecOps Native GoogleSQL (`events`) |
| :--- | :--- |
| `FROM \`{{PROJECT_ID}}.secops_linked_data.events_table\`` | `FROM events` |
| `udm.metadata.log_type` | `metadata.log_type` |
| `udm.principal.user.userid` | `principal.user.userid` |
| `WHERE target.ip IN ('224.0.0.251')` | `WHERE EXISTS (SELECT 1 FROM UNNEST(target.ip) AS ip WHERE ip = '224.0.0.251')` |
| `WHERE event_time_bucket >= TIMESTAMP_SUB(...)` | Handled via API time bounds (`time_unit="DAY"`, `time_value="7"`) or omitted in WHERE |

## Phase 1: High-Volume Known Noise Elimination

### 1.1 Broadcast & Multicast Noise
Multicast discovery protocols (mDNS on 5353, SSDP on 1900) generate high event volumes with zero threat value across enterprise networks. Note: NetBIOS (137) and LLMNR (5355) should be **retained** because they are abused in credential coercion and relay attacks (Responder).

```sql
SELECT
  metadata.log_type,
  target.port,
  COUNT(1) AS event_count
FROM events
WHERE EXISTS (
  SELECT 1 FROM UNNEST(target.ip) AS ip
  WHERE ip IN (
    '224.0.0.251',     -- mDNS IPv4
    '239.255.255.250', -- SSDP IPv4
    '224.0.0.252'      -- LLMNR IPv4
  )
  OR ip LIKE 'ff02::%' -- IPv6 Multicast
)
OR target.port IN (5353, 1900)
GROUP BY 1, 2
ORDER BY event_count DESC
```

**Recommended Action**: Filter at source agent / BindPlane processor or network edge.

---

### 1.2 Loopback Traffic IPC (`127.0.0.0/8`, `::1`)
Loopback network events generated by local IPC (e.g., microservices communicating with local proxies) rarely indicate intrusion unless paired with anomalous process context.

```sql
SELECT
  metadata.log_type,
  target.port,
  principal.process.file.full_path,
  COUNT(1) AS event_count
FROM events
WHERE EXISTS (
  SELECT 1 FROM UNNEST(target.ip) AS tip
  WHERE tip LIKE '127.%' OR tip = '::1'
)
AND EXISTS (
  SELECT 1 FROM UNNEST(principal.ip) AS pip
  WHERE pip LIKE '127.%' OR pip = '::1'
)
GROUP BY 1, 2, 3
ORDER BY event_count DESC
LIMIT 50
```

**Recommended Action**: Suppress loopback traffic where process full path is a verified system binary (e.g. systemd, local monitoring agents) and port is static.

---

### 1.3 Windows Filtering Platform (WFP 5156/5158 vs. EDR)
WFP Connection Allowed events (Event ID 5156) and Bind Allowed events (Event ID 5158) generate astronomical log volumes that duplicate EDR network connection events.

```sql
SELECT
  metadata.product_event_type,
  COUNT(1) AS event_count
FROM events
WHERE metadata.log_type IN ('WINEVTLOG', 'MICROSOFT_WINDOWS_SECURITY')
  AND metadata.product_event_type IN ('5156', '5158')
GROUP BY 1
```

**Recommended Action**: If EDR network connection telemetry (CrowdStrike, Defender, SentinelOne) is ingested, completely disable WFP Connection Success auditing via GPO:
`Auditpol /set /subcategory:"Filtering Platform Connection" /success:disable`

---

### 1.4 Windows Security: Micro-filtering Automated Logons (Event ID 4624)
Interactive logons (Type 2, 10) must be captured for forensic tracking. Automated logons (Type 3 Network, Type 4 Batch, Type 5 Service) from machine accounts create massive noise.

```sql
SELECT
  extensions.auth.mechanism,
  target.user.userid,
  COUNT(1) AS event_count
FROM events
WHERE metadata.log_type IN ('WINEVTLOG', 'MICROSOFT_WINDOWS_SECURITY')
  AND metadata.product_event_type = '4624'
  AND (target.user.userid LIKE '%$' OR target.user.userid LIKE 'DWM-%')
GROUP BY 1, 2
ORDER BY event_count DESC
LIMIT 50
```

**Recommended Action**: Suppress logon Type 3 and 4 events where `target.user.userid` ends in `$` at the forwarder/agent configuration.

---

### 1.5 Windows Process Execution: Micro-filtering `svchost.exe` (Event ID 4688)
Generic Service Host invocations lacking child process arguments generate high volume.

```sql
SELECT
  principal.process.file.full_path AS parent_process,
  target.process.file.full_path AS child_process,
  target.process.command_line,
  COUNT(1) AS event_count
FROM events
WHERE metadata.log_type IN ('WINEVTLOG', 'MICROSOFT_WINDOWS_SECURITY')
  AND metadata.product_event_type = '4688'
  AND target.process.file.full_path = 'C:\\Windows\\System32\\svchost.exe'
  AND principal.process.file.full_path = 'C:\\Windows\\System32\\services.exe'
GROUP BY 1, 2, 3
ORDER BY event_count DESC
LIMIT 50
```

**Recommended Action**: Micro-filter standard background system service invocations at the forwarder while retaining anomalous command-line flags (`-k`, unquoted service paths).

---

### 1.6 Linux Auditd: Automated Schedulers & Monitoring Agents
Linux cron jobs, monitoring agents (node-exporter, datadog-agent), and config management (chef, puppet, ansible) flood `auditd` logs.

```sql
SELECT
  principal.process.file.full_path,
  principal.user.userid,
  COUNT(1) AS event_count
FROM events
WHERE metadata.log_type = 'NIX_SYSTEM'
  AND principal.user.userid IN ('root', 'system')
  AND principal.process.file.full_path IN (
    '/usr/sbin/cron',
    '/usr/sbin/crond',
    '/usr/bin/node_exporter',
    '/opt/datadog-agent/bin/agent'
  )
GROUP BY 1, 2
ORDER BY event_count DESC
LIMIT 50
```

## Phase 2: Log Source Redundancy & Vantage Point Validation

Identify identical network events captured simultaneously across multiple vantage points (e.g., Firewall + Web Proxy + EDR):

```sql
SELECT
  metadata.log_type,
  COUNT(1) AS event_count
FROM events
WHERE metadata.event_type = 'NETWORK_CONNECTION'
GROUP BY 1
ORDER BY event_count DESC
```

## Phase 3: Volume vs. Alert Ratio (Value Proxy)

Assess the security detection density of each log source by comparing total events ingested to events associated with a detection or alert:

```sql
SELECT
  metadata.log_type,
  COUNT(1) AS total_events,
  COUNTIF(ARRAY_LENGTH(security_result) > 0) AS events_with_security_results,
  ROUND(SAFE_DIVIDE(COUNTIF(ARRAY_LENGTH(security_result) > 0), COUNT(1)) * 100, 4) AS security_yield_pct
FROM events
GROUP BY 1
ORDER BY total_events DESC
LIMIT 50
```

## Phase 4: Data Quality & Normalization Audits

### 4.1 Unnormalized Usernames (Email address in userid field)
```sql
SELECT
  metadata.log_type,
  principal.user.userid,
  COUNT(1) AS occurrences
FROM events
WHERE principal.user.userid LIKE '%@%'
GROUP BY 1, 2
LIMIT 50
```

### 4.2 Ingestion Latency / Timestamp Clock Drift
Identifies collectors or log sources with clock skew between `metadata.event_timestamp` and `metadata.collected_timestamp`:

```sql
SELECT
  metadata.log_type,
  AVG(TIMESTAMP_DIFF(metadata.collected_timestamp, metadata.event_timestamp, SECOND)) AS avg_latency_seconds,
  MAX(TIMESTAMP_DIFF(metadata.collected_timestamp, metadata.event_timestamp, SECOND)) AS max_latency_seconds
FROM events
WHERE metadata.collected_timestamp IS NOT NULL
  AND metadata.event_timestamp IS NOT NULL
GROUP BY 1
HAVING avg_latency_seconds > 300 OR avg_latency_seconds < -60
ORDER BY avg_latency_seconds DESC
```
